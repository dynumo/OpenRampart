# Object storage

OpenRampart stores every original file, and its derived previews, in an S3-compatible bucket.
It uses only standard S3 operations: `PutObject` (multipart for large files), `GetObject`
(with ranges), `HeadObject`, `DeleteObject`, `HeadBucket` and optionally `CreateBucket`. Any
provider that implements these works.

## Layout

```
<S3_KEY_PREFIX>originals/<ownerId>/<attachmentId>          the uploaded file, byte-for-byte
<S3_KEY_PREFIX>derived/<ownerId>/<attachmentId>/thumbnail.webp  small thumbnail
<S3_KEY_PREFIX>derived/<ownerId>/<attachmentId>/preview.webp page-sized preview
```

Keys are generated by the server and never contain user-supplied names. The original filename
is kept in the database and used for downloads, together with the SHA-256 computed while
the upload streamed in. The background worker downloads and re-hashes the stored object
afterwards to confirm it arrived intact.

## Requirements

- The bucket must be **private**. OpenRampart streams files to signed-in users itself and never
  hands out public or pre-signed URLs.
- The credentials need read, write, delete and list on the bucket, plus create if
  `S3_CREATE_BUCKET=true`. Grant nothing more.
- Enable server-side encryption if the provider offers it.
- Consider **versioning** or **object lock** for an extra layer against accidental or
  malicious deletion. OpenRampart deletes objects only when an item is purged from the Trash.

## Provider examples

### Cloudflare R2

```sh
S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
S3_REGION=auto
S3_BUCKET=openrampart
S3_ACCESS_KEY_ID=<R2 API token access key>
S3_SECRET_ACCESS_KEY=<R2 API token secret>
```

Create an R2 API token with **Object Read & Write**, limited to the bucket.

### Backblaze B2

```sh
S3_ENDPOINT=https://s3.eu-central-003.backblazeb2.com
S3_REGION=eu-central-003
S3_BUCKET=openrampart
S3_ACCESS_KEY_ID=<keyID>
S3_SECRET_ACCESS_KEY=<applicationKey>
```

Use an application key restricted to the bucket. Keep the bucket private.

### Hetzner Object Storage

```sh
S3_ENDPOINT=https://fsn1.your-objectstorage.com
S3_REGION=fsn1
S3_BUCKET=openrampart
S3_ACCESS_KEY_ID=…
S3_SECRET_ACCESS_KEY=…
```

### AWS S3

```sh
S3_ENDPOINT=
S3_REGION=eu-west-2
S3_BUCKET=openrampart-<something-unique>
```

Use an IAM user or role whose policy allows `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject`
and `s3:ListBucket` on this bucket only. Keep Block Public Access on.

### MinIO (self-hosted)

```sh
S3_ENDPOINT=http://minio:9000
S3_FORCE_PATH_STYLE=true
S3_BUCKET=openrampart
S3_CREATE_BUCKET=true
```

### SeaweedFS (bundled)

`docker-compose.yml` includes an optional SeaweedFS service (`COMPOSE_PROFILES=bundled-s3`). Its
S3 credentials are generated from `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY`.

```sh
COMPOSE_PROFILES=bundled-s3
S3_ENDPOINT=http://s3:8333
S3_FORCE_PATH_STYLE=true
S3_CREATE_BUCKET=true
```

Its data lives in the `s3-data` volume, so back that volume up.

## Sharing a bucket

Set `S3_KEY_PREFIX` (for example `openrampart/`) to keep OpenRampart's objects together. Do not
point two OpenRampart installations at the same bucket and prefix.

## Checking

`/readyz` returns `{"storage":"ok"}` when the bucket is reachable. **Settings → System
settings** shows the storage status, and **Settings → Storage and trash** shows how much your
record uses, with OCR and integrity status.

## Moving between providers

1. Put OpenRampart into maintenance by stopping the app.
2. Copy every object, keeping keys, with `rclone sync old:bucket new:bucket`.
3. Change the `S3_*` settings and start the app.
4. Open a few attachments and choose **Verify now**. This re-downloads the original and
   compares its SHA-256 with the hash recorded at upload.

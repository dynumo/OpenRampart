# Accessibility

OpenRampart is used by people under pressure: dealing with official letters, deadlines and
disputes, sometimes while unwell, disabled, or with limited time and energy. Accessibility is
therefore a core requirement. The target is **WCAG 2.2 level AA** throughout.

## What is built in

### Structure and navigation

- A "Skip to main content" link, landmarks (`header`, `nav`, `main`) and one `h1` per page.
- On navigation, focus moves to the new page's heading and the document title changes, so
  screen readers announce where you are.
- Native HTML controls throughout. Modals use the native `<dialog>` element, which traps focus
  and returns it afterwards. The Actor picker is a labelled text field with a list of buttons,
  not a fragile custom combobox.
- Every page works with a keyboard alone. There are no keyboard traps, and the focus order
  follows the visual order.

### Forms

- Every field has a visible label. Hints and errors are linked with `aria-describedby`.
- On a failed submit, an **error summary** at the top lists each problem as a link to its
  field. Errors are written in plain language, saying what to do rather than what went wrong.
- Required fields are marked in text, not by colour alone. Only the essentials are required:
  an Event needs a type and a date, nothing else.
- Correct `autocomplete`, `inputmode` and `type` values are used, for example for one-time
  codes, email addresses and dates.

### Feedback

- Status messages (saved, uploading page 2 of 3, OCR progress) are announced through polite
  live regions. Errors use `role="alert"`.
- Filters apply when submitted rather than on every keystroke, so results are not announced
  repeatedly.

### Visual design

- The "Rain & Wind On Rathlin" palette (light and dark), generated by ChromaJev, meets AA
  contrast for text and UI components.
- Light and dark modes follow the system setting, with a per-device override under
  **Settings → Account → Appearance**.
- Focus indicators are a 3px outline with offset, visible in both themes and in forced-colour
  (high contrast) modes.
- Text resizes to 200% and reflows down to 320 CSS pixels wide without horizontal scrolling.
- Touch targets are at least 44×44 CSS pixels (WCAG 2.5.8 requires 24×24).
- `prefers-reduced-motion` turns off transitions.
- Status is never shown by colour alone. Risk levels, timestamp states and integrity results
  always have text.

### Content

- Calm, plain language. Dates are written in full ("12 September 2026"). Jargon is
  avoided or explained.
- Thumbnails that duplicate a link's text use empty `alt`. Document previews describe what they
  are and point to the recognised text, which is the accessible alternative to an image of a
  letter.

### Phone use

- Responsive layout with bottom navigation on small screens.
- Letter capture opens the camera directly, with large buttons and announced progress.
- Installable as a PWA.

## Testing

### Automated

- **ESLint** with `eslint-plugin-jsx-a11y` (strict) on every change.
- **axe-core** in Playwright end-to-end tests (`tests/e2e/`) checks rule sets `wcag2a`,
  `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa` on these screens:
  - registration, two-step set-up, sign-in and the second-factor step;
  - the timeline (empty, desktop, mobile and dark mode);
  - the Event type picker, Event form and Event page;
  - Actors list, Actor timeline, Incident timeline and search results;
  - letter capture (empty and with pages) and the document viewer with OCR text;
  - Helper invitation, accepting an invitation, and the Helper's restricted Event view;
  - account settings (dark mode), security settings, the Audit Log and MCP connections;
  - the OAuth consent screen.

  Any violation fails CI.

- A reflow test loads the timeline, an Event, the Event form, search and settings at 320 CSS
  pixels wide and fails if any page scrolls horizontally (WCAG 1.4.10).

Automated tools find only part of the issues, so manual checks remain essential.

### Manual checks (before each release)

- [ ] Complete the main journeys with the keyboard only: register, record an Event, capture a
      letter, search, invite a Helper, connect an MCP client.
- [ ] Screen readers: NVDA + Firefox, VoiceOver + Safari (macOS and iOS), TalkBack + Chrome.
- [ ] 200% and 400% zoom; 320px width; text spacing overrides.
- [ ] Windows High Contrast (forced colours).
- [ ] Voice control (Voice Access or Voice Control): visible labels match accessible names.
- [ ] Error recovery: submit empty and invalid forms and follow the error summary.

## Reporting a problem

Accessibility problems are bugs. Please open an issue with the page, what you were trying to
do, the assistive technology and browser you use, and what happened. If you cannot use GitHub,
see [../SECURITY.md](../SECURITY.md) for a contact route.
